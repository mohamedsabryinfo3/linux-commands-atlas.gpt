01 / PACKAGE MODEL

APT ليس بديلًا مطابقًا لـ DNF

كلاهما يدير الحزم والاعتماديات، لكن صيغة الحزم والمستودعات وآلية الاستعلام تختلف.

02 / SECURITY MODEL

AppArmor مقابل SELinux

كلاهما يضيف Mandatory Access Control، لكن طريقة كتابة السياسات وتشخيص المنع مختلفة.

03 / NETWORK MODEL

NetworkManager هو الأساس في Rocky 10

استخدم nmcli وملفات keyfile الحديثة؛ لا تعتمد على ifcfg / network-scripts القديمة في Rocky 10.

RELEASE PHILOSOPHY

افهم طريقة وصول التحديثات

01

Fixed / Stable

إصدار رئيسي مستقر تُختار فيه الحزم بعناية، وتصل التحديثات وفق سياسة الإصدار. مثال شائع: Debian Stable.

02

LTS / Enterprise Lifecycle

دعم وصيانة طويلان نسبيًا، مع اهتمام بالاستقرار والتحديثات الأمنية. تختلف التفاصيل حسب الموزع والمنتج.

03

Rolling Release

تحديثات مستمرة بدل الانتقال بين إصدارات رئيسية ثابتة. تحتاج متابعة الأخبار وملاحظات التحديثات قبل الترقية.

04

Declarative / Image-based

تُعرّف حالة النظام أو الصورة المطلوبة بطريقة قابلة لإعادة الإنتاج؛ فلسفة مختلفة عن إدارة كل تغيير يدويًا.

PACKAGE MANAGEMENT / KEY DISTINCTION

Package format ≠ Package manager

صيغة الحزمة هي شكل الملف وقاعدة بيانات مكوناته، أما مدير الحزم فهو الأداة التي تحل الاعتماديات وتتعامل مع المستودعات والتثبيت والتحديث.

DEBdpkg منخفض المستوى + apt كواجهة إدارة عالية المستوى.
RPMrpm منخفض المستوى + dnf أو zypper لإدارة المستودعات والاعتماديات.
Otherpacman أو apk أو xbps أو emerge أو nix حسب التوزيعة.
FIELD NOTE / YOU DO NOT NEED TO INSTALL ALL OF THEM

لدراستك العملية الحالية استمر على Debian وRocky. هذه الموسوعة لتوسيع الصورة العامة فقط؛ لا تضف توزيعة ثالثة إلى المعمل لمجرد أن اسمها ظهر هنا.
